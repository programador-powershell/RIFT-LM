# VLB Native Runtime Contract v1

## Objective

VLB is a self-contained model execution technology. A verified VLB deployment MUST NOT require llama.cpp, bitnet.cpp, FreeToken, GGML/GGUF runtimes, PyTorch, Transformers, ONNX Runtime, vLLM, or another LLM inference engine at runtime.

Python/PyTorch/Transformers MAY be used only on the conversion/reference side to obtain the upstream reference outputs and to build a VLB artifact.

Runtime ownership is split into four VLB-owned layers:

1. **VLB1 model container** — deterministic binary container with explicit tensor metadata and hashes.
2. **VLB Kernel** — native C/C++ kernels for quantized matmul and future transformer operators.
3. **VLB Model Runtime** — architecture executor, KV cache, tokenizer and VLB/AMT adaptive path.
4. **VLB Server** — native HTTP service exposing VLB runtime directly.

## Non-negotiable scientific rule

No compression ratio, RAM reduction, throughput or quality number may be inferred from a formula and published as a measured result.

A deployment profile is promoted only from measurements generated by the real VLB artifact and real VLB runtime.

## Retention terminology

`KR100` means **100% pass on the frozen certification contract**, not mathematical proof that every possible behavior of the upstream model is identical.

A model/profile may be called `VLB_KR100_CERTIFIED` only when all frozen certification units pass the configured per-unit criteria against the immutable reference runtime/output ledger.

A reconstruction cosine, NRMSE, perplexity average, benchmark average, or aggregate top-1 improvement is never sufficient by itself.

## Proof ladder

### P0 — Container integrity

Required:

- deterministic model/tensor IDs;
- per-tensor SHA-256;
- full artifact SHA-256;
- exact byte sizes measured from the produced artifact;
- no full upstream checkpoint required by the VLB runtime.

Status: `VLB1_CONTAINER_INTEGRITY_PASS`.

### P1 — Native kernel equivalence

For tensors taken from the real converted model, execute the exact same activation vector through:

- reference dequantize + FP32 operation;
- VLB native kernel.

Record max absolute error, RMSE, NRMSE and cosine from actual outputs.

No hard-coded performance claim is allowed. Thresholds are part of the test contract and raw metrics are retained.

Status: `VLB_NATIVE_KERNEL_NUMERIC_PASS`.

### P2 — Native architecture replay

The entire model forward must execute through VLB-owned code. No fallback into Transformers/PyTorch/llama/bitnet is permitted.

Runtime reports must include:

- model artifact SHA-256;
- server/kernel git revision;
- CPU/GPU identity;
- peak RSS / VRAM measured by the process;
- prompt/token counts;
- wall time and measured tokens/s;
- deterministic output ledger where applicable.

Status: `VLB_NATIVE_MODEL_RUNTIME_PASS`.

### P3 — KR100

Replay the frozen certification set through both:

- immutable upstream/canonical reference;
- native VLB runtime.

Every unit must pass. Aggregate improvements do not rescue a failed unit.

Status: `VLB_KR100_CERTIFIED` only at `passed == total`.

### P4 — AMT

AMT is teacher-free. The base VLB model is immutable during AMT proof. Training data, gate-development data and final certification data must be disjoint.

AMT may add learned residual/state-conditioned modules and a marginal-gain STOP/CONTINUE gate. It may not silently rewrite the certified base route.

Status: `VLB_AMT_CERTIFIED` only after fresh validation and KR100 replay.

## First target: google/gemma-4-E4B-it

The first end-to-end native target is `google/gemma-4-E4B-it`.

The first profile is intentionally conservative:

- source: official Safetensors;
- streaming conversion: one source tensor resident at a time;
- VLB quantized Linear weights: Q8 group size 64;
- sensitive/tied embedding weights: retained at a higher precision until a lower precision profile independently passes KR100;
- text path is certified first; multimodal behavior requires a separate frozen image-text certification set.

## Runtime dependency rule

The final `vlb-server` executable may link only to the operating system C/C++ runtime and explicitly audited low-level system libraries. It must not dynamically invoke another LLM runtime executable or Python process.

## Current implementation boundary

The first native milestone implements and tests the VLB1 container plus native Q8_G64 GEMV/GEMM primitives and a native HTTP server shell.

This milestone MUST NOT be reported as full Gemma runtime or KR100. Full certification starts only after all required Gemma transformer operators, tokenizer, KV cache and sampling execute inside VLB-owned native code.
